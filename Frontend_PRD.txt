# PRD: Multi‑Tenant Scalable Platform — Backend + Frontend

**Purpose:**
This document is a full, actionable Product Requirements Document (PRD) and implementation plan for a multi‑tenant SaaS platform with a TypeScript backend (MySQL) and a Next.js + Tailwind admin frontend. It contains features, architecture, detailed step‑by‑step work items (>=40 steps), and ready‑to‑use Cursor prompts for every step so you can automate scaffolding and implementation.

---

# 1. High Level Goals

* Build a secure, scalable multi‑tenant platform with tenant isolation and SuperAdmin control.
* Provide dynamic modules and menus (submenus supported), RBAC with tenant + global roles.
* Unified login (superadmin + tenant users) with `is_superadmin` flag support.
* Full API standards: pagination, search, sorting, filtering, standardized response format, Zod validation.
* Frontend: Next.js + Tailwind UI with shadcn components, skeleton loaders, error boundaries, custom modal & confirmation modal, TanStack Query for data fetching, Axios, Redux Toolkit + Redux Persist.
* Testing: Jest + Supertest (backend), Playwright (frontend) or Playwright for e2e — E2E environment using a MySQL test DB.
* Observability: Audit logs, request logging, metrics-ready design.

---

# 2. Key Features (summary)

* Multi‑tenant data model (tenants, users with tenant\_id, roles, modules, role\_permissions)
* Modules & dynamic menus with nesting (parent\_id) and ordering
* RBAC: role\_permissions per module/submodule; `can_view_all` or `scope` (`own/all`)
* Auth: JWT access + refresh (rotation), login devices tracking, revoke device
* API standards: structured JSON response, error format, Zod validation
* Search, Filter, Sort, Pagination (cursor & offset)
* Support system: tickets, replies, attachments
* Audit logs for all critical actions
* Frontend: authGuard, skeleton loaders, error boundary, shadcn modals, notification library, confirmation modal
* Testing & CI: Jest unit/integration, Supertest e2e, Playwright UI e2e, CI pipelines, migrations

# 3. API Response Standard

All APIs must return this shape:

```json
{
  "success": true|false,
  "message": "string",
  "data": any,               // optional
  "errors": any|null,        // optional
  "meta": {                  // optional for lists
    "page": 1,
    "limit": 10,
    "total": 100,
    "cursor": "..."        // optional for cursor pagination
  }
}
```

Use HTTP status codes appropriately: 200, 201, 204, 400, 401, 403, 404, 422, 500.

Add indexes on tenant\_id, user\_id, created\_at and searchable fields (name, email, title).

# 6. Authorization Flow

* Middleware (server) sequence:

  1. authMiddleware (verify JWT, attach user object)
  2. tenantResolver (derive tenant context from token/subdomain/header)
  3. permissionGuard(moduleKey, action) — checks merged permissions from global roles + tenant roles + tenant overrides; bypass if user.is\_superadmin

* permission resolution rules: merge all roles assigned to user → union of permissions; tenantRolePermissions override global ones for the tenant when present.

---

# 7. Frontend AuthGuard behavior

* Protect pages using `AuthGuard` component/hook which:

  * checks auth token validity (via TanStack Query auth state)
  * ensures `is_active` and tenant active flag
  * resolves permissions (from Redux + React Query) before rendering
  * shows skeleton loaders while permissions load
  * redirects to login if unauthenticated or unauthorized

# 8. Features by Module (functional breakdown)

Below each module lists the API features, validation, permissions, and UI expectations.

## 8.1 Auth

* Endpoints: `/auth/login`, `/auth/logout`, `/auth/refresh`, `/auth/forgot`, `/auth/reset`, `/auth/revoke-device`
* Validation: email, password, tenantSlug (optional)
* Workflow: login → issue access token (short) + refresh token (httpOnly cookie) + store refresh token record + login\_device record
* Permissions: None
* Frontend: Login form, forgot password, device list and revoke

## 8.2 Tenants (SuperAdmin)

* Endpoints: CRUD, list (filters, pagination, search), settings override, activate/deactivate
* Permissions: SuperAdmin only
* Frontend: Tenant management UI, tenant detail, tenant settings

## 8.3 Users

* Endpoints: CRUD (with invite token flow), list (filters, search, pagination), assign roles
* Permissions: TenantAdmin can manage within tenant; SuperAdmin across tenants
* Frontend: Users table, create/edit user modal, role assignment UI

## 8.4 Roles & Permissions

* Endpoints: roles CRUD, assign permissions per module/submodule
* Data: role\_permissions rows for each (role, module, CRUD flags, can\_view\_all)
* Frontend: Role editor with permission matrix UI (modules x actions) and save

## 8.5 Modules & Menus

* Endpoints: modules CRUD, submodule CRUD, reorder endpoint
* Frontend: Menu builder UI; sidebar consumes menu for current user

## 8.6 Support System

* Endpoints: tickets CRUD, replies, attachments upload, list (filters, search, pagination). Admin scopes: tenant vs global
* Frontend: Ticket list, ticket detail, reply composer with attachments

## 8.7 Audit Logs

* Endpoints: list, single, export
* Filters: action, user, date range, module
* Frontend: Audit viewer with filters & export

## 8.8 Login Devices / Sessions

* Endpoints: list devices per user, revoke device, revoke all
* Frontend: Device list with revoke action and session counts

# 14. Detailed Summary for Self‑Development (How to learn & implement this)

This section explains how a developer should approach learning and implementing the project. It contains recommended reading, sequence for learning, and tips for debugging and testing.

## Learning Path (4–8 weeks plan)

1. **Week 1 — TypeScript & Node.js Essentials**

   * Strongly type JavaScript, generics, union types
   * Express + TypeScript patterns
   * Async/await and error handling
2. **Week 2 — Databases & Prisma**

   * Relational modeling, indexing
   * Prisma schema & migrations
   * Transaction handling
3. **Week 3 — Security & Auth**

   * JWT (RS256 vs HS256), token rotation
   * OWASP top 10, secure headers
4. **Week 4 — Advanced Backend**

   * RBAC models, permission resolution algorithms
   * Pagination & cursor-based pagination
5. **Week 5 — Frontend Advanced**

   * Next.js + Tailwind + shadcn UI
   * TanStack Query + Redux Toolkit
   * Error boundaries, modals, skeletons
6. **Week 6 — Testing & DevOps**

   * Jest & Supertest, Playwright
   * Docker, CI, automated migrations

## Debugging tips

* Reproduce with integration tests first.
* Use consistent request-id logs for tracing.
* For auth issues, inspect JWT payload and expiry timestamps.

## Performance tips

* Index search fields, use pagination, limit joins.
* Cache frequently-read tenant settings in Redis if needed.
* Use connection pooling and prepared statements.

## How to iterate

* Start with minimal MVP: auth, tenants, users, roles, modules.
* Add support and audit logs next.
* Add full frontend features after stable APIs.
* Keep PRs small and test-driven.
