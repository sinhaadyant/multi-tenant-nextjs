## Step 9: Implement AuthGuard and Route Protection

**Goal:** Create a higher-order component to protect routes based on authentication and permissions.

**Implementation Details:**
- Create AuthGuard component that checks authentication
- Implement permission-based route protection
- Handle loading states while checking auth
- Redirect to login for unauthenticated users
- Show unauthorized page for insufficient permissions

**Permission Checking Logic:**
- Check if user is authenticated
- Verify user is active and tenant is active
- Check specific permissions (canCreate, canRead, canUpdate, canDelete, canViewAll)
- Handle data scope based on permissions:
  - **Superadmin**: Can see ALL tenant data across the platform
  - **canViewAll**: Can see all data within their tenant
  - **canRead only**: Can see only their own data
- Handle superadmin bypass logic

**Cursor Prompt:**
```
Create route protection system with:
1. AuthGuard component that wraps protected routes
2. Permission checking logic that uses Redux auth state with granular permissions (canCreate, canRead, canUpdate, canDelete, canViewAll)
3. Data scope resolver that determines if user can see all data vs own data only
4. Loading spinner while authentication is being verified
5. Automatic redirect to /login for unauthenticated users
6. Unauthorized page component for insufficient permissions
7. usePermissions hook to check specific permissions with scope handling
8. Route-level permission checking with module and action parameters
9. Integration with Next.js App Router middleware or page-level protection
10. Superadmin bypass logic for all restrictions
```
